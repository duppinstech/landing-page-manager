## 1. Setup path

**Headline: Set up a client landing page in WordPress**

Add a client under **Landing Pages → Clients**, choose a site-wide design in **Landing Pages → Settings → Templates**, then create a page and assign its client and keyword. DNS and server routing remain part of your site's setup. https://github.com/duppinstech/landing-page-manager

## 2. Published-page result

**Headline: One WordPress workflow, a client-specific page link**

After publish, the generated HTTPS link uses the assigned client's slug and the landing page's slug, while the selected template controls the page layout. Check the result on your configured subdomain before sharing it. https://github.com/duppinstech/landing-page-manager

## 3. Template choice

**Headline: Keep a consistent layout across client pages**

Landing Page Manager includes Template A, Template B, and Template C templates. Choose one in **Landing Pages → Settings → Templates**; core applies that selection site-wide rather than assigning a separate template to each client. https://github.com/duppinstech/landing-page-manager

## 4. Organize campaigns

**Headline: Keep pages findable by client and keyword**

Use the Clients and Keywords menus to organize the records connected to landing pages. The Landing Pages list also includes an **Export CSV** action for exporting the page list. https://github.com/duppinstech/landing-page-manager

## 5. Failure path

**Headline: Check the logs before asking for help**

If a page fails, record its public URL and check the site's PHP/web-server logs; WordPress `debug.log` is available only when debug logging is configured. Then email support@duppinstech.com or call (240) 397-8221 with the relevant error details, not a customer's contact information. https://github.com/duppinstech/landing-page-manager
