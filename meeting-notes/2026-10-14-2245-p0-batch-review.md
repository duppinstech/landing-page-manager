  - Should the internal planning docs stay in the public repo?

## Smoke test
This is the release gate for this batch, from ops. Run it on staging with WP 5.9 + PHP 7.4, then the latest WP + PHP 8.3, with `WP_DEBUG` and `WP_DEBUG_LOG` on and Query Monitor installed.

1. **Baseline on 1.0.6.** Install v1.0.6 and set up:
   - one Template B page;
   - one Template C page with `<br>` in the hero heading and an `<iframe>` in "More" content;
   - Template A pages in styles 1, 2 and 3;
   - a client with a Place ID and brand colours.

   On a second copy, make an uploaded template active. Take screenshots and Network-tab captures.
2. **Upgrade through the updater.** Use a mu-plugin that filters `lpmanager_github_releases_api_url` to a staging JSON file (`tag_name: v1.0.7` with a `landing-page-manager.zip` asset). Check:
   - the plugin stays in the `landing-page-manager/` folder;
   - nothing fatals;
   - the debug log is clean.
3. **Updater after the upgrade.**
   - The Updates tab shows only the info text.
   - "Check for updates" works.
   - The release cache transient exists.
   - A stubbed GitHub failure causes no fatal error and offers no update.
4. **Uploaded template (second copy).**
   - The red notice, with its link, shows on every admin screen.
   - Pages show the custom 404.
   - Re-uploading clears both.
5. **Template B.**
   - `jQuery.fn.jquery` is WordPress's own version.
   - No requests for `jquery-migrate-new`, `bootstrap-new`, `payform`, or jsDelivr on the front end.
   - No front-end `fetch_google_reviews` call.
   - The reviews slider is clipped, pauses on hover and stops on focus.
   - The map info window shows name, address and phone.
6. **Template C.**
   - Every section, card and heading is visible normally, with reduced motion on, and with JS disabled.
   - The `<br>` in the hero renders as a line break.
   - Safari gets `is_safari`.
   - No requests for `swiper.js`, `bootstrap.js` or `popper`.
7. **Template A (styles 1, 2 and 3).**
   - The hero is visible at once, with JS off and with reduced motion on.
   - The scroll reveal works otherwise.
   - Blocking `main.js` still shows the content after 3 seconds.
   - JSON-LD passes the Rich Results Test, and invalid JSON prints nothing.
8. **Visual comparison against the baseline:** colours, layout, and how the iframe in rich text renders (it's now stripped, pending Odell's decision).
9. **Google keys.**
   - Restrict the browser key with `https://site/*` and `https://*.site/*`, and the server key by IP.
   - Client geocoding fills in lat/lng and the Place ID.
   - Fetch Reviews works, and a second click makes no outbound call.
   - A bad Place ID shows the "did not recognise" message, and a repeat within 10 minutes makes no call.
   - An Author can't fetch on someone else's page.
   - With an empty server key, the browser key is used.
10. **CSV export.**
    - The button appears for admins only.
    - Its URL has `_wpnonce` and the filters.
    - A page titled `=1+1` exports as `'=1+1`.
    - Requests without the nonce are refused.
    - There's exactly one button and one dashboard widget.
11. **Privacy:** under Settings → Privacy → Policy Guide, "Copy suggested policy text" copies only the suggested paragraphs.
12. **Release artifacts.**
    - The zip contains no `lint.log`, `.claude`, `PLAN.md`, `meeting-notes` or template `*.html`.
    - `git archive HEAD` excludes the same paths.
13. **CI.** Push the branch:
    - lint passes on PHP 7.4, 8.1 and 8.3;
    - a throwaway PR with a parse error fails;
    - then close that PR.
14. **Rollback:** reinstall 1.0.6. Nothing fatals, and pages, settings and keys are intact. Lift the browser key's restriction before this step.
15. **Uninstall (throwaway copy).**
